# 深度研究一键自动启动 — 设计

**状态：** 已实现  

**日期：** 2026-08-11  
**方法论：** SDD  
**用户选型：** 深度研究作为**自动化 skill**：建议卡确认后，在上下文充足时直接 `startRun`，不再强制手填预检表单。  
**关联模块：** `AIAnalysis`、`ResearchAgentPanel`、`researchAgentIntent`  
**关联：** 流式输出见 `2026-08-11-ai-chat-streaming-design.md`（本变更不改流式管道）  

## 1. 问题

用户在聊天中触发「深度研究」意图后，需再点建议卡 → 打开预检弹窗 → 手填/确认问题与标的 → 再点「开始深度研究」。短问题（如「深度研究走势」&lt; 10 字）还会导致提交按钮禁用，体感「不能提交、还要自己填」，与「自动化 skill」预期不符。

## 2. 目标

1. 建议卡点「启动深度研究」= **确认执行 skill**：预检就绪且能解析 ≥1 个 A 股主体时，**自动 `startRun`**，关闭建议卡并展示运行账本/进度。  
2. 研究问题过短时，用会话上下文（最近用户/助手消息、讨论标题、已解析股票）**自动扩写**到 ≥10 字的合格问题，禁止卡在空表单。  
3. **仅在无法自动启动时**打开现有预检弹窗（缺主体、预检未就绪、全局已有 running 租约等），并带上预填内容与错误原因。  
4. 「改为普通问答」行为不变。不自动荐股、不自动交易。

## 3. 非目标

- 不取消预检/预算确认语义的主进程校验（`confirmedBudgetVersion` 等仍由 `startRun` 携带）。  
- 不在用户未点建议卡时静默自动开跑（仍需一次显式确认）。  
- 不改造产业研究下一期入口。  
- 不改变深度研究全局单 running 租约。

## 4. 行为

| 条件 | 行为 |
|---|---|
| 预检 `ready` 且主体 ≥1 且问题可扩写合格 | 静默 `startRun`，toast「深度研究已启动」 |
| 预检失败 / 无主体 / startRun 失败 | 打开原弹窗，预填问题与建议股票，展示原因 |
| 全局已有 queued/running | 不 start；toast 或弹窗提示等待/取消 |

自动扩写规则（前端派生，可单测）：

- 若 `question.trim().length >= 10` 且含可解析股票上下文则用原问题。  
- 否则模板：`对 {名称或代码} 做深度研究：{用户原句}。结合本地行情、基本面与受信证据，给出可验证结论与缺口。`  
- 仍不足 10 字则追加会话最近一条非空用户消息摘要（截断）。

主体来源优先级：preflight `suggestedSubjects` 中的 stock → 从当前会话消息/`STOCK_CODES`/标题解析的代码。

## 5. 验收

| # | 期望 |
|---|---|
| A | 会话已有明确股票时，点建议「启动深度研究」后无需再点弹窗即可出现 running 账本 |
| B | 短意图句（&lt;10 字）不再单独导致无法启动 |
| C | 无股票上下文时仍打开弹窗要求确认主体 |
| D | 忙碌租约时不双开运行 |
| E | 无荐股/自动交易文案 |

## 8. 修订（2026-08-11）

用户明确：建议卡确认后即为 **多 agent / skill 调度**，**禁止再弹预检表单**。  
失败时仅 toast / 面板内错误提示，由系统从会话正文提取 `tsCode`（含括号内六位代码）自动组主体；产业项目主体也自动确认。隐藏的 E2E「打开预检」入口仍保留弹窗供手工调试。
