# 复盘报告自动附带 AI 研判段落 — 设计

**状态：** 已批准  

**日期：** 2026-08-10  
**方法论：** SDD  
**关联模块：** `DecisionCenter`（FR-233 / FR-236 复盘报告；FR-239「和 AI 讨论」；本需求 FR-250）  
**用户确认：** **日报 + 周报一起做**；生成时**自动**调用 AI 研判（非可选按钮）  
**批准：** 用户「按照规范推进吧」（2026-08-10）；开放问题默认锁定见 §9。

## 1. 问题

今日/本周复盘报告当前是**本地事实聚合**（摘要、已处理、未处理风险、证据缺口、待验证、弱声明/免责声明），用户可见智能入口主要是保存成功后的「和 AI 讨论」（打开研究讨论会话）。

用户已配置 LLM，希望在**一键复盘 / 生成本周复盘**时，报告本身就带一段 **AI 研判**，而不是只能跳进聊天再问一遍。动机是「已接模型 → 复盘应体现智能能力」，同时保留本地统计真相源。

## 2. 目标

1. **范围：** 今日复盘（`daily`）与本周复盘（`weekly`）**一并**纳入；入口仍为现有「一键复盘」/「生成本周复盘」（及与之等价的生成路径）。  
2. **触发：** 本地事实报告构建完成并展示后，**自动**发起一次模型调用；抽屉内对 AI 段落展示加载态。  
3. **产出：** 报告内独立「AI 研判」区块，**随报告快照一并持久化**；文案强调风险/不确定/待验证，**禁止**荐股、买卖点、收益承诺、仓位指令。  
4. **失败策略（软失败）：** AI 失败或未配置时，**保留**本地聚合报告并可正常保存；抽屉内给出清晰错误/引导，**不阻断**本地事实落盘。  
5. **成本：** 每次成功走完生成路径默认 **1 次**模型调用；复用现有 AI 配置解析与 `callWithFallback`（或等价主进程回退链）。  
6. **保留**「和 AI 讨论」：自动研判是报告内嵌段落，讨论仍是保存后的交互追问入口，二者不互相替代。

## 3. 非目标

- 不引入自动交易、自动下单、仓位控制或荐股产品能力。  
- 不替换或弱化本地统计段落（摘要/已处理/风险/缺口/待验证仍由本地派生，AI 不得改写这些字段的事实内容）。  
- 不移除「和 AI 讨论」，不把自动研判做成必须打开的聊天会话。  
- 不在本设计中做后台定时复盘、批量对历史报告补跑 AI、或多模型并行对比。  
- 不因本需求改变左侧导航信息架构或另造独立「AI 复盘」一级入口。  
## 4. 产品不变量（必须写入实现与验收）

来自根目录 `AGENTS.md` / `CONTRIBUTING.md`，本功能不得削弱：

| 不变量 | 本设计中的含义 |
|---|---|
| 本地优先 | 本地事实先构建、先可见、可单独保存；联网/模型调用需用户已配置 AI，且失败不毁掉本地报告 |
| 窄 IPC + 主进程校验 | 模型调用只走主进程；Renderer 不持有凭据、不直连模型 API |
| 不荐股 / 不收益承诺 / 不自动交易 | Prompt、解析后展示与复制文本均禁止买卖建议、目标价/仓位指令、收益承诺；免责声明保留 |
| 可追溯 | AI 段落与生成时刻、provider/model（若可得）一并进入快照或旁路元数据，便于历史回看 |
| 不篡改账本语义 | 同周期再生成走现有版本链（新 `requestId` → 新 version）；不静默改写更早版本的本地事实 |

## 5. 推荐方案（锁定默认）

### 5.1 触发与范围

| 项 | 锁定 |
|---|---|
| 报告种类 | **daily + weekly** |
| 触发时机 | 用户点击生成（一键复盘 / 生成本周）→ 本地 `build*ReviewReport` 成功 → **自动**调 AI 一次 |
| 是否可选按钮 | **否**。用户已确认「自动」；不做「生成 AI 研判」二次按钮作为主路径 |
| 与讨论关系 | 自动段落写入报告；「和 AI 讨论」仍要求报告已保存后可用（FR-239 不变） |

**已否决（备查）：**

- 仅日报或仅周报先做（用户已确认一起做）。  
- 仅打开讨论、报告内无固定段落。  
- 主路径改为可选「生成 AI 研判」按钮（与「自动」冲突）。

### 5.2 端到端流程

```text
用户：一键复盘 / 生成本周
  → 打开抽屉 + 本地报告 loading
  → 本地聚合成功：立刻展示本地段落，并 queue 保存本地快照（可先无 AI 或 AI=pending）
  → AI loading（抽屉内「AI 研判」区）
  → 成功：写入 aiNarrative（及元数据）→ 更新 UI → 再持久化含 AI 的快照（新保存或同轮补写，plan 锁定一种）
  → 失败 / AI_NOT_CONFIGURED：本地报告保留；AI 区显示友好错误；本地保存不回滚
```

要点：

1. **本地事实不被 AI 阻塞：** 聚合失败才算整单失败；AI 失败不算整单失败。  
2. **抽屉 loading 分层：** 整页/报告级 loading 仅覆盖本地构建；AI 有独立小节 loading，避免「本地已出却整页空白」。  
3. **一次生成一次调用：** 同一次点击不因 UI 重渲重复打模型；需用 in-flight / request 代际取消过期回调。

### 5.3 AI 研判内容形态

报告模型在现有 `ReviewReport` 上扩展（名称以实现为准，语义锁定）：

- `aiNarrative: { status, text, generatedAt?, provider?, model?, errorCode?, errorMessage? }` 或等价结构。  
- UI：独立小节标题「AI 研判」；位于本地段落之后、免责声明附近（plan 可微调顺序，但必须可辨认非本地统计）。  
- 纯文本复制（`formatReviewReportText`）须包含该节（失败时可省略正文或写明「AI 研判未生成：…」）。  
- Prompt 输入：**以本报告本地事实为主**（可复用 FR-239 讨论桥接里对 daily/weekly review 的摘要/上下文拼装思路），必要时附极少量组合语境；禁止把未授权外网热点当硬事实写入。  
- 输出约束（系统提示必须写明）：
  - 使用风险、不确定、证据不足、待验证语言；
  - **禁止**具体买卖点、加仓减仓指令、收益/胜率承诺、荐股清单；
  - 不声称替代用户判断；可与现有 `disclaimer` 呼应。

解析策略（实现可选其一，plan 锁定）：优先结构化短字段（如「关注点 / 风险 / 待验证」）再拼展示；或单一 Markdown/纯文本段落。无论哪种，落库后历史打开须可还原。

### 5.4 再生成 / 覆盖策略

同一自然日（或同一周报周期）用户再次点击生成：

| 策略 | 锁定 |
|---|---|
| 本地事实 | **重建**（与现 FR-233 一致） |
| AI 段落 | **重新调用模型并覆盖**新一版报告中的 AI 节（不复用旧 AI 文案冒充新事实） |
| 历史版本 | 沿用 FR-236：新 `requestId` 产生新 `versionNumber`；不覆盖更早版本行 |
| 确认弹窗 | **默认不弹**「是否覆盖 AI」（与「自动 + 再点即再生成」一致）。若日后要省配额确认，另开修订 |

说明：再生成会消费配额；可通过抽屉内「AI 研判生成中」与按钮 disable 防止连点双发。

### 5.5 配置与错误

| 情形 | 行为 |
|---|---|
| 已配置且调用成功 | 展示并保存 AI 段落 |
| `AI_NOT_CONFIGURED` / 无可用凭据 | 友好提示（引导去 AI 配置）；本地报告正常 |
| 超时 / 供应商错误 / 解析失败 | 明确错误文案；本地报告正常；可选「重试 AI 研判」仅重跑 AI（不计为第二套主 CTA；若做，仍单次调用） |
| 用户关闭抽屉时 AI 仍在飞 | 允许后台完成则静默落盘，或取消过期请求（plan 二选一；不得因关抽屉删掉已保存的本地版） |

复用：`callWithFallback` / 现有 AI 配置解析；不在 Renderer 新造一套 key 读取。

### 5.6 与「和 AI 讨论」的边界

| | 自动 AI 研判 | 和 AI 讨论 |
|---|---|---|
| 形态 | 报告内只读段落 | 研究讨论会话（可追问） |
| 时机 | 生成后自动 | 保存成功后手动 |
| 持久化 | 进入 `decision_review_reports` 快照 | `ai_analysis_sessions` 等既有讨论存储 |
| 目的 | 一眼看到模型对本次复盘的归纳 | 深入追问、整理变更等 |

自动研判**不是**讨论会话的第一条消息的唯一来源；实现上可共享 prompt/上下文拼装工具函数，但产品表面保持两入口。

## 6. 架构与预期触点（批准后 plan 细化）

| 层级 | 预期 |
|---|---|
| Renderer | `DecisionCenter` 生成流：本地成功后触发 AI；`ReviewReportPanel` 增 AI 区与 loading/error；`reviewReportModel` 类型与 `formatReviewReportText` |
| Preload / IPC | 新增窄 IPC（如 `decision:generateReviewAiNarrative`）或复用既有 AI IPC 并带 review 快照校验；禁止 Renderer 直连模型 |
| Main | 服务：组 prompt → `callWithFallback` → 校验/消毒输出 → 返回；可读已保存 report id 或接受可信本地快照摘要（须防任意 prompt 注入扩大） |
| DB | 优先：**扩展 snapshot JSON** 容纳 `aiNarrative`（旧快照无字段视为「无 AI」）；避免仅为该字段新建表。若校验层 `DecisionReviewReportSnapshot` 过严，放宽可选字段（向前兼容，不破旧行） |
| README | 实现时更新 `src/components/DecisionCenter/README.md`（新 FR 或扩展 FR-233/236 说明） |

不引入自动交易相关模块；不改信号生命周期语义。

## 7. 验收标准

1. 「一键复盘」生成今日报告后，抽屉在本地段落实后出现「AI 研判」；成功时有模型正文且已写入可再打开的历史快照。  
2. 「生成本周复盘」行为对称（同样自动一次 AI）。  
3. AI 未配置或调用失败时：本地报告仍展示且可保存；错误信息可读；不因 AI 失败回滚本地保存。  
4. 复制纯文本在成功时包含「AI 研判」内容。  
5. 同日/同周期再次生成：本地重建 + AI 重新调用并出现在新版本；旧版本历史仍可打开且不被静默篡改。  
6. 「和 AI 讨论」仍在保存后可用；未因本功能删除或强制替代。  
7. 输出与 prompt 约束体现不变量：无买卖建议/收益承诺/自动交易话术；保留风险与免责语境。  
8. 单次生成路径默认至多一次模型调用（重试 AI 为显式二次动作）。  
9. 实现阶段更新 `DecisionCenter/README.md`；相关单测覆盖软失败、快照字段兼容、格式化文本含 AI 节。

## 8. 风险与缓解

| 风险 | 缓解 |
|---|---|
| 模型输出越权（类荐股） | 强系统约束 + 可选后处理拒收明显违规句式；UI 旁注「辅助研判，非投资建议」 |
| 生成变慢 / 体感卡顿 | 本地先出；AI 区独立 loading；按钮防连点 |
| 双保存竞态（先本地后 AI） | 单一 pending 代际；AI 回写只更新本轮 report；plan 明确「补写同 version vs 新 version」 |
| 快照体积 | 限制 AI 正文长度上限；维持现有 512 KiB 快照上限意识 |
| 与讨论上下文重复烧配额 | 自动研判与讨论分离；不在生成时自动开讨论会话 |

## 9. 开放问题 — 批准时锁定默认

| # | 问题 | 锁定 |
|---|---|---|
| 1 | AI 成功后的持久化 | **同轮补写同一 version**（`requestId` 幂等行上 UPDATE `snapshot_json`，不因 AI-only 强开新 version） |
| 2 | 内容形态 | **单段落**纯文本 + 长度上限（不强制三节结构） |
| 3 | 关闭抽屉时 in-flight AI | **取消**：递增代际，忽略过期回调；不删已保存本地版；关抽屉后**不**再后台补写 AI |
| 4 | 「仅重试 AI」 | **提供**：AI 失败/缺失时小链接；显式二次动作；仍单次模型调用 |

## 10. 批准清单（已确认）

1. **范围：** 今日复盘 + 本周复盘 **一起做**。  
2. **触发：** 生成后 **自动**调用 AI 一次（非主路径可选按钮）。  
3. **软失败：** AI 失败/未配置 → 保留本地报告与保存；抽屉内清晰错误。  
4. **产出：** 报告内「AI 研判」段落并进入快照；风险/不确定语言；**无**荐股/买卖/收益承诺/自动交易。  
5. **再生成：** 本地重建 + AI 重调覆盖新版报告中的 AI 节；旧 version 不篡改。  
6. **保留**「和 AI 讨论」；不替换本地统计。  
7. **复用**现有 AI 配置与 `callWithFallback`（或等价）；`AI_NOT_CONFIGURED` 友好提示。  
8. 产品不变量（本地优先、窄 IPC、不荐股、可追溯）写入实现与验收。  
9. §9 四项开放问题默认已锁定。
