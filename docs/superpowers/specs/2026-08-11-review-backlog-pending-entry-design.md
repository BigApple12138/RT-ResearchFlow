# 复盘积压入口接到待复盘处置 — 设计

**状态：** 已完成  
**日期：** 2026-08-11  
**用户确认：** 方案 A（点积压 → 待复盘列表 + 可进明细/研判收口）

## 1. 问题

指挥区「复盘积压」数字来自近 30 日未收口信号，点击却打开「历史复盘报告」列表，用户无法处理积压。右侧「复盘提示详情」虽有「待复盘」Tab，默认不从此入口打开，且列表偏只读。

## 2. 目标

1. 点「复盘积压」打开复盘提示详情抽屉，**默认 Tab = 待复盘**。  
2. 待复盘条目可进入事件明细 / 研判以收口（复用既有抽屉，不新造状态机）。  
3. 指标数字用 `summary.unresolved`（真实未收口数）；列表 limit 提到足够展示（如 30）。  
4. 「历史复盘 / 看复盘」仍打开报告历史，职责分离。  
5. 更新 `DecisionCenter/README.md`。

## 3. 非目标

- 不批量一键收口、不改信号生命周期语义。  
- 不把积压绑到一键复盘报告。

## 4. 验收

1. 点积压 → 待复盘列表，不是历史报告。  
2. 列表条目可打开明细/研判。  
3. 数字与 `unresolved` 一致（可大于列表截断条数时，hint 仍写近 30 日待收口）。  
4. 历史复盘入口行为不变。
