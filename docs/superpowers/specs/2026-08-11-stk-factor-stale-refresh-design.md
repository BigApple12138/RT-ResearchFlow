# 技术因子缓存落后自动补拉 — 设计

**状态：** 已完成  
**日期：** 2026-08-11  

## 问题

`shortTerm:getStockFactor` 默认加载时若本地已有任意最新 `stk_factor_cache` 行即返回，不与最近交易日比较，导致行情已更新而底部技术因子停在旧日（如 8/7）。

## 目标

默认加载时：若最新缓存 `tradeDate` **严格落后于** `getLatestTradeDateYmd(db)`，且 Tushare 已启用，则尝试拉取目标日（失败可再试无日期最新）；成功则 upsert 并返回新行；失败则回退旧缓存（仍带旧日期）。  
精确指定 `tradeDate` 的请求行为不变（命中缓存即返回；未命中再拉）。

## 非目标

- 不把因子做成盘中秒级；不改为本地日线自算 MACD 替代 Tushare 面板  
- 不强制全市场定时刷因子（本批仅打开个股/调用 getStockFactor 路径）  
- 不改筹码同路径（可后续对称）  

## 验收

1. 缓存日 &lt; 最近交易日 + Tushare 开 → 调用拉取；成功后面板日期追上（或上游仅有更近日则返回该日）。  
2. Tushare 关或拉取失败 → 仍返回旧缓存，不空白。  
3. 缓存已 ≥ 最近交易日 → 不发起上游。  
4. 单测覆盖；`StockChart/README.md` 注明。
