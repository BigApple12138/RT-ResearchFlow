# 待复盘列表快捷收口与批量处置 — 设计

**状态：** 已完成  
**日期：** 2026-08-11  
**用户确认：** 方案 A（行内快捷 + 多选批量）  
**关联：** `2026-08-11-review-backlog-pending-entry-design.md`

## 1. 问题

待复盘列表只能点「事件明细」进抽屉填表，条数多时无法高效收口。

## 2. 目标

1. 待复盘（及重复触发）每行增加快捷：`有效收口`、`噪音忽略`；备注可选（默认可空）。  
2. 支持多选 + 顶部「批量有效收口 / 批量噪音忽略」。  
3. 「事件明细 / 研判」保留，用于要写长备注的情形。  
4. 复用既有 `decision.resolve` / `decision.dismiss`；成功后刷新复盘统计与今日信号。  
5. 更新 `DecisionCenter/README.md`。

## 3. 非目标

- 不新造生命周期状态；不自动交易。  
- 不做「一键全部未收口」无确认大杀器（批量仅作用于**当前勾选**）。  
- 不改一键复盘日结。

## 4. 行为锁定

| 动作 | IPC | 默认 |
|---|---|---|
| 有效收口 | `resolve(id, 'RESOLVED_VALID')` | note 可空 |
| 噪音忽略 | `dismiss(id, '噪音/快捷忽略')` 或 `resolve(..., 'RESOLVED_DUPLICATE')` | **锁定 dismiss**，与抽屉「忽略」一致 |
| 批量 | 对勾选 id 串行/有限并发调用同上；部分失败汇总提示 | 需至少勾选 1 条 |

列表勾选仅在待复盘 / 重复触发 Tab；降噪建议仍为只读洞察。

## 5. 验收

1. 单条快捷后该项离开待复盘（或刷新后减少），积压数字下降。  
2. 多选批量可一次处理多条。  
3. 事件明细仍可用。  
4. 未勾选时批量按钮禁用。
