# 今日看板「一键复盘」可见入口 — 设计

**状态：** 已实现待检核（代码未 commit）  

**日期：** 2026-08-10  
**方法论：** SDD  
**用户选型：** **方案 3**（主按钮生成今日复盘 + 「看复盘」/「复盘积压」进历史复盘）  
**关联模块：** `DecisionCenter`（今日看板）既有 FR-201 / FR-233 / FR-236 复盘能力  
**关联 plan：** [`../plans/2026-08-10-today-dashboard-one-click-review-entry.md`](../plans/2026-08-10-today-dashboard-one-click-review-entry.md)

## 1. 问题

用户在「今日看板」感到**没有复盘入口**：

- 指挥区真实动作「生成今日复盘 / 生成本周复盘 / 历史复盘」目前**仅在组合视图**（`viewMode === 'portfolio'`）露出；切换到「全部信号」后主路径上像「没有复盘」。
- 持仓风险侧栏「建议入口 → 看复盘」是**静态文案**，不可点击，强化「无入口」感。
- 首屏指标「复盘积压」只读，数字无法导向待收口/历史。
- 左侧导航没有独立「复盘」项（本设计**不**新增导航项）。

用户期望有一处显眼的「一键复盘」。

## 2. 目标

在今日看板用**最少表面改动**把既有复盘闭环接到显眼入口：

1. **主 CTA「一键复盘」**：指挥区 footer 常显（组合 **与** 全部信号视图皆可见），点击后走与现「生成今日复盘」相同路径：即时生成并打开**今日复盘**报告抽屉（`ReviewReportPanel` + 既有保存逻辑）。
2. **「看复盘」可点**：持仓风险迷你面板「建议入口」在文案为「看复盘」时变为真实控件，打开**历史复盘**抽屉（`ReviewReportHistoryPanel`，与现「历史复盘」按钮同一表面）。
3. **「复盘积压」可点（推荐默认，一并纳入本批）**：关键指标卡点击后打开**同一**历史复盘抽屉，避免「数字有积压却无处去」。
4. 实现时同步更新 `src/components/DecisionCenter/README.md` 行为说明（见 §7）。

## 3. 非目标

- **不**新建复盘引擎、报告 schema、Migration、新 IPC。
- **不**新增左侧导航「复盘」一级项。
- **不**改日/周报告派生算法、弱声明规则、讨论桥接契约。
- **不**把「一键复盘」做成周报、判断记录或盘前推演的聚合入口。
- **不**在本批重构指挥区信息架构或精筛布局。
- 本文件批准前：**不写 plan、不改业务代码、不 commit**。

## 4. 用户选型（方案 3）与推荐默认

| 入口 | 行为（锁定） |
|---|---|
| 指挥区主按钮「一键复盘」 | **生成/打开今日复盘报告**（等同现 `handleGenerateDailyReview` / `decision-generate-daily-review`） |
| 「建议入口」中的「看复盘」 | **打开历史复盘抽屉**（等同现 `decision-review-report-history` → `ReviewReportHistoryPanel`） |
| 「复盘积压」指标卡 | **同上：打开历史复盘抽屉**（推荐默认，本批纳入） |

**已否决的替代（记录备查，不实现）：**

- 一键 = 只打开历史列表、不生成今日报告。
- 「看复盘」= 再生成今日报告（与主按钮重复，且「看」语义不符）。
- 仅组合视图才显示「一键复盘」（无法解决「非组合像无入口」）。

## 5. 交互设计

### 5.1 指挥区「一键复盘」

- **位置：** `decision-command-footer` 内，与「刷新」同排；视觉为**主按钮**（相对「刷新」更醒目，可沿用现「生成今日复盘」的 cyan 强调样式或等价 primary）。
- **可见性：** **不依赖** `isPortfolioView`。市场视图与组合视图均展示。
- **文案：** 「一键复盘」（用户可见主标签）。内部可保留/兼容 `data-testid="decision-generate-daily-review"`，或新增 `decision-one-click-review` 并在实现时让测试双认——plan 锁定一个主 testid，避免双源真相。
- **点击：** 调用既有今日复盘生成流：打开 `ReviewReportPanel`、`buildDailyReviewReport(...)`、异步 `saveReviewReport`。无信号日仍生成「持仓平稳」短报告（FR-233 不变）。
- **与旧按钮关系：**
  - 组合视图下原「生成今日复盘」可被「一键复盘」**替换**（避免同排双按钮同义）；「生成本周复盘」「历史复盘」「判断记录」仍可仅组合视图保留。
  - 市场视图：仅新增「一键复盘」；不强制露出周报/判断记录（非本批目标）。
- **加载态：** 复用现有 `reviewReportLoading` / 抽屉 loading，防止连点重复刷屏（与现日复盘一致即可）。

### 5.2 「看复盘」链接化

- **位置：** `PortfolioRiskMiniPanel` 行「建议入口」。
- **条件：**
  - 当建议值为「看复盘」时：渲染为 `button`/`link` 样式控件，`onClick` → `setReviewReportHistoryOpen(true)`（或抽一层与指挥区历史按钮共用的 handler）。
  - 当建议值为「补成本价」时：**保持现状语义**（本批可不做成跳转；若已有成本补齐路径可复用，**不得**误开历史复盘）。
- **可访问性：** 可键盘聚焦；有明确可点击样式（下划线或按钮态），不得再像纯 `<b>` 文本。
- **testid：** 如 `decision-suggest-open-review`（plan 锁定）。

### 5.3 「复盘积压」可点

- **位置：** 关键指标中 `label === '复盘积压'` 的 `CommandMetric`。
- **点击：** 与「看复盘」相同 → 打开历史复盘抽屉。
- **实现注意：** 仅该卡可点；「高优先级 / 持仓风险 / 短线机会」本批保持只读，避免指标区变成随意导航矩阵。
- **反馈：** `button` 语义或 `role="button"` + focus ring；可加 `title`/aria-label「打开历史复盘」。
- **指标公式不变：** 仍用 `reviewStats.pendingReview` 等既有派生；本批只加导航，不改统计定义。

### 5.4 信息架构（用户心智）

```text
一键复盘     →  生成/打开「今日」报告（做事）
看复盘 /
复盘积压     →  打开「历史复盘」列表（回看 / 待收口归档入口）
```

历史抽屉内既有「生成今日复盘」空态 CTA 可保留，作为次级路径，与主 CTA 同 handler。

## 7. 验收标准

1. 在「全部信号」视图下，指挥区仍可见并可点「一键复盘」，无需先切到「组合」。  
2. 点击「一键复盘」打开今日复盘抽屉，内容与现组合视图「生成今日复盘」同源；可复制/保存行为不回退。  
3. 「建议入口」为「看复盘」时可点击并打开历史复盘抽屉；为「补成本价」时不误开历史。  
4. 「复盘积压」可点击并打开**同一**历史复盘抽屉；其余三张关键指标仍不可点。  
5. 无新复盘引擎、无新 IPC/Migration、无左侧导航新项。  
6. **实现阶段**更新 `DecisionCenter/README.md`：写明一键复盘常显、与日复盘等价；写明看复盘/积压 → 历史复盘；注明组合视图下周报/历史/判断记录按钮策略。  
7. 相关单测（及必要 E2E）覆盖上述入口；实现完成后按仓库惯例跑相关 verify 子集。

## 8. 风险与缓解

| 风险 | 缓解 |
|---|---|
| 市场视图用户以为「一键」会复盘全市场信号 | README + 抽屉内容仍标明组合/持仓语境（沿用 FR-233 报告结构）；不新造「全市场复盘」承诺 |
| 「复盘积压」数字来自 pendingReview，历史抽屉是报告列表，略有语义差 | 文案保持「复盘积压」；点击进既有历史复盘（方案 3 明确选择）；不在本批另造待收口专用页 |
| 组合视图按钮过多 | 用「一键复盘」替换同义「生成今日复盘」，周报/历史/判断保留为次级 |
| 双 testid / 文案漂移 | plan 锁定主 testid 与可见文案表 |
